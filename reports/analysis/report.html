LLM 프롬프트 압축의 코딩 에이전트 성능 영향 평가

Terminal Bench 2.1 · DeepSWE 종단 측정 · LLMLingua-2 · 최종 추론 gpt-5.4 · 작성일 2026-09-04

요약

⚠️ 측정이 아직 진행 중입니다. 압축 조건 비교(조건별 22~44/22 trial) · DeepSWE(조건별 6~12/6 trial) — 조건별 표본 수가 서로 다르므로 아래 수치는 잠정값이며, 롤아웃 완료 후 갱신됩니다. 확정 결과로 인용하지 마십시오.

코딩 에이전트의 프롬프트에 LLMLingua-2 프롬프트 압축을 적용하고 정확도와 토큰 사용량 변화를 측정하였습니다. Terminal Bench 2.1 공식 하네스로 태스크 11종 × 6개 조건(154 trial), DeepSWE 공식 하네스로 태스크 3종 × 6개 조건(42 trial)을 비교하였으며, 최종 추론은 전 조건 동일하게 Azure AI Foundry 의 gpt-5.4 로 수행하였습니다.

압축 강도를 높일수록 pass@1 이 하락하는 경향이 관측되었습니다. 기준 조건 61.4% 대비 가장 강한 압축(rate 0.5)에서 27.3%(-34.1%p)였습니다.

입력 토큰은 5/5 개 조건에서 감소하였으며 최대 감소는 llmlingua2-r0.5 의 -50.0% 였습니다. 태스크 단위 대응 비교에서 토큰이 증가한 사례는 에이전트 스텝 증가를 동반하였으며, 압축으로 손상된 컨텍스트가 추가 탐색을 유발하여 절감분을 상쇄한 것으로 해석됩니다.

부하 규모가 다른 두 벤치마크를 함께 측정하였습니다. DeepSWE 는 누적 입력이 Terminal Bench 의 25배 규모입니다. 이 규모에서는 토큰이 실제로 감소했으나(최대 -38.8%), 이슈 해결 진척도(f2p)가 67.3% 에서 44.9% 이하로 떨어졌습니다. trial 소요 시간은 최대 7배로 늘었습니다.

다만 동일 조건을 반복 측정한 압축 없이 반복 측정에서 pass@1 이 ±18.2%p, 입력 토큰이 ±20.3% 범위로 변동하였습니다. 관측된 변화의 상당 부분이 이 변동 범위 내에 있으므로, 경향은 확인되나 효과의 크기는 현재 표본(조건당 11종 × 1회)으로 확정할 수 없습니다. 결론 적용 시 이 점을 함께 고려하여야 합니다.

1. 개요

본 평가는 프롬프트 압축을 코딩 에이전트 워크로드에 적용했을 때 비용 절감과 정확도 손실의 상충 관계를 정량화하는 것을 목적으로 합니다.

프롬프트 압축은 모델 입력 토큰을 줄여 비용과 지연을 낮추는 기법입니다. 요약·검색 기반 컨텍스트 축소와 달리 원문 토큰 중 일부를 선별 삭제하며, 별도의 생성 모델을 호출하지 않으므로 오버헤드가 작습니다. 본 평가에서는 Microsoft LLMLingua-2 를 대상으로 하였습니다.

평가 범위

본 보고서는 공식 하네스로 에이전트를 실제 실행하고 저장소 테스트로 채점한 종단 측정만 수록합니다. 두 벤치마크를 사용하였으며, 부하 규모가 크게 다르므로 함께 측정하였습니다.

DeepSWE 는 실제 오픈소스 저장소의 이슈를 해결하는 벤치마크로, Terminal Bench 와 동일한 Harbor 계열 스키마를 사용합니다. 채점 시 f2p(해결해야 할 테스트)와 p2p(유지해야 할 테스트)를 분리 제공하므로, 통과하지 못한 경우에도 진척도를 비교할 수 있습니다.

제외한 항목은 압축기만 단독 실행하여 수정 대상 파일을 지목할 수 있는지 확인한 컴포넌트 단위 대리 측정입니다. 에이전트를 실행하지 않으므로 pass@1 을 산출할 수 없어 정확도 근거로 사용하지 않았습니다. 해당 결과는 reports/llmlingua2-grid/ 및 reports/llmlingua-deepswe/ 에 별도 보관되어 있습니다.

또한 채점 컨테이너의 의존성 설치 실패로 테스트가 실행되지 않은 측정 회차가 있었으며, 해당 회차는 전량 제외하고 재측정한 결과만 수록하였습니다.

9. 결론 및 권고

측정 결론

코딩 에이전트 프롬프트 전체에 LLMLingua-2 를 일괄 적용한 결과, pass@1 이 61.4% 에서 27.3% 로 -34.1%p 하락하였습니다. 압축 강도가 높을수록 하락 폭이 커졌으며, 압축 조건이 통과한 태스크는 기준 조건 통과 태스크의 부분집합이었습니다.

입력 토큰은 감소하였으나 관측된 절감률이 반복 측정 변동 범위 내에 있어, 현재 표본으로는 비용 절감 효과를 확정할 수 없습니다.

압축기 자체의 동작은 정상이었습니다. 부록의 입출력 예시에서 확인되듯 산문형 입력은 절반 수준으로 압축하여도 핵심 정보가 보존됩니다. 반면 명령 실행 출력에서는 식별자가 손상되며, 에이전트는 해당 식별자로 후속 명령을 구성하므로 이 손상이 성능 저하의 직접적 경로로 작용합니다.

종합하면, 현 시점에서 프로덕션 적용을 권고하기에는 근거가 부족합니다. 정확도 저하 경향과 토큰 증폭 현상이 일관되게 관측되었으므로, 전체 일괄 적용 대신 아래 방향의 선택적 적용을 검토하고 표본을 확대하여 재측정할 것을 제안합니다.
