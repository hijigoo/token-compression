# compare/ — 실행 결과를 가로질러 비교하기

랩 하나의 결과는 `runs/` 에 쌓입니다. 여기서는 **여러 랩·여러 조건을 나란히
놓고** 봅니다. 원본 코퍼스를 직접 읽지 않고 이미 나온 결과만 씁니다.

| 파일 | 하는 일 |
|---|---|
| `qa_eval.py` | 압축된 컨텍스트로 **실제로 답할 수 있는지** 평가합니다 |
| `results/` | 남길 가치가 있는 결과입니다. 커밋됩니다 |

`runs/` 는 커밋하지 않습니다. 개발하면서 돌린 실행이 타임스탬프 폴더로 수십
개씩 쌓여 잡음이 되기 때문입니다. 대신 `results/` 는 **"무엇을 알아냈나"**
단위라 실행 횟수와 무관하게 개수가 유지됩니다.

## qa_eval.py — 보존율이 정말 맞는 지표인가

### 왜 필요한가

랩이 쓰는 **정답 보존율**은 문자열 검사입니다. 값싸고 빠르지만 두 방향으로
틀립니다.

```
원문   주말 및 공휴일에는 접수되지 않습니다      must_include: ["않습니다"]
요약   주말·공휴일 제외                        → 보존율 0%
       ↑ 뜻은 지켰는데 0% 로 셉니다
```

반대도 있습니다. 숫자를 그대로 베끼면서 문맥을 흐리는 요약은 100% 로 셉니다.
즉 보존율은 **하한**입니다 — 낮으면 확실히 문제지만 높다고 안전하지 않습니다.

### 어떻게 재나

```
원문      + 질문  →  기준 답변
압축본    + 질문  →  대상 답변  →  판정(같음/다름)
```

기준 답을 사람이 미리 적어두지 않는 이유는, 표현이 조금만 달라도 틀렸다고
세게 되기 때문입니다. **같은 모델**에게 원문을 통째로 주고 낸 답을 기준으로
삼으면 압축 때문에 생긴 차이만 남습니다. 모델 실력은 양쪽에서 상쇄됩니다.

판정은 셋입니다.

| 판정 | 뜻 | 위험도 |
|---|---|---|
| 정답 | 기준 답변과 같은 내용입니다 | — |
| **오답** | 정보가 없는데 **지어냈습니다** | **높음** |
| 모름 | 정보가 없다고 인정했습니다 | 낮음 |

**오답과 모름을 반드시 나눠서 보세요.** 둘 다 답을 못 한 것이지만, 모름은
사용자가 알아챌 수 있는 안전한 실패이고 오답은 그렇지 않습니다.

### 실행

```bash
python compare/qa_eval.py --corpus sample
python compare/qa_eval.py --corpus sample --limit 3      # 먼저 조금만
```

랩을 다시 돌리지 않습니다. `runs/**/records.jsonl` 에 압축 전후가 둘 다
남아 있어서 그걸 읽습니다. 케이스당 기준 답변 1회 + 조건마다 (답변 1회 +
판정 1회) 이고, 모름으로 끝나면 판정은 건너뜁니다. 전부 캐시됩니다.

## 결과 — `sample` 12건

| 랩 / 설정 | 절감 | 보존율 | **정답률** | 오답 | 모름 |
|---|---|---|---|---|---|
| 00 기준선 | 0.0% | 100% | **100%** | 0% | 0% |
| 01 무손실 (산문) | 0.8% | 100% | **100%** | 0% | 0% |
| 02 참조핸들 `k1-short` | -2.0% | 79.2% | **58.3%** | 8.3% | 33.3% |
| 03 요약 `plain-short` | 57.2% | 33.3% | **58.3%** | 0% | 41.7% |
| 03 요약 `preserve-short` | 59.5% | 88.9% | **91.7%** | 8.3% | 0% |

### 읽어야 할 것 네 가지

**1. 보존율은 실제로 하한이었습니다.**
`plain-short` 는 보존율 33.3% 인데 정답률은 58.3% 입니다. 문자열이 사라져도
뜻이 남아 답할 수 있는 경우가 그만큼 있었습니다. 지표가 실패를 과장하고
있었던 것이 수치로 확인됐습니다.

**2. 지시를 준 요약이 모든 축에서 낫습니다.**
`preserve-short` 는 `plain-short` 보다 **더 줄이면서**(59.5% vs 57.2%)
**더 맞혔습니다**(91.7% vs 58.3%). 압축률과 정확도가 반드시 맞바꿔야 하는
관계가 아니라는 것을, 이번에는 정답률로도 확인했습니다.

**3. 압축을 세게 하면 모델이 기권합니다.**
`plain-short` 는 오답이 0% 인데 모름이 41.7% 입니다. 정보가 통째로 사라지면
모델이 지어내지 않고 "모름" 이라고 답했습니다. **정보를 어중간하게 남기는
것보다 확실히 지우는 편이 안전할 수 있다**는 뜻입니다.

**4. 보존율 100% 인데 답을 못 한 경우가 있습니다.**
가장 중요한 발견입니다. `doc-003` 은 두 조건에서 정답 문자열이 다 남았는데도
답이 갈렸습니다.

```
질문   심야에도 환불 신청이 가능한가?
정답 문자열   ["않습니다", "22시~06시"]

02 참조핸들   …심야 시간대(22시~06시)에는 시스     ← 다이제스트가 문장 중간에서 잘림
              보존율 100% · 판정 모름
```

문자열은 둘 다 남았지만 **문장이 잘려서 뜻이 성립하지 않습니다.** 보존율은
이걸 못 잡습니다. 다이제스트 길이로 자르는 방식의 구조적 약점입니다.

## 이 지표의 한계도 함께 봐야 합니다

QA 평가가 완벽한 잣대는 아닙니다. 위 결과에서 `preserve-short` 의 오답 1건은
확인해 보니 **압축은 충분했는데 답변이 불완전했던** 경우였습니다.

```
압축 결과   환불 신청은 09시부터 18시까지 접수, 22시~06시 처리되지 않습니다.
                                                ↑ 정보는 있습니다
답변        환불 신청은 09시부터 18시까지 접수됩니다.
                                                ↑ 심야를 언급하지 않아 '다름' 판정
```

즉 **답변 품질과 판정 엄격도라는 잡음이 섞입니다.** 보존율이 값싸고 결정적인
대신 둔하다면, 정답률은 예민한 대신 흔들립니다. 둘을 같이 보는 이유입니다.

| | 보존율 | 정답률 |
|---|---|---|
| 비용 | 0 (문자열 검사) | 케이스당 2~3회 호출 |
| 재현성 | 완전히 같음 | 모델·판정에 따라 흔들림 |
| 잡아내는 것 | 명백한 소실 | 뜻의 소실 |
| 놓치는 것 | 표현 변화, 문장 절단 | — |

**보존율로 빠르게 거르고, 정답률로 확인하는 순서**를 권합니다.

## 자가 점검

기준선(`00-baseline`)은 압축을 하지 않으므로 원문과 같은 텍스트입니다.
따라서 **정답률이 100% 여야 합니다.** 아니면 채점이 불안정하다는 뜻이고,
그 상태의 다른 숫자는 믿을 수 없습니다. 어긋나면 **exit 1** 입니다.
