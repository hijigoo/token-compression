# token-compression

LLM 컨텍스트 압축 기법을 **같은 조건에서 나란히 비교**하는 실험 저장소입니다.

"이 기법은 몇 % 줄여줍니다" 같은 말은 흔하지만, 무엇을 기준으로 잰 것인지,
줄이면서 무엇을 잃었는지는 잘 드러나지 않습니다. 이 저장소는 그 두 가지를
항상 함께 재도록 만들어 두었습니다.

## 측정 결과부터 보시려면

공식 벤치마크 하네스로 에이전트를 실제 실행해 얻은 결과가 있습니다.

| 문서 | 분량 | 언제 |
|---|---|---|
| [`reports/analysis/brief.html`](reports/analysis/) | 짧음 | **먼저 여기**. 결론·핵심 표·권고만 |
| [`reports/analysis/report.html`](reports/analysis/) | 김 | 설계·파라미터 정의·전체 표·부록까지 |

Terminal Bench 2.1 과 DeepSWE 를 `pier`(공식 러너) + Docker 격리로 돌리고,
태스크에 포함된 테스트로 채점했습니다. 압축은 에이전트와 모델 사이 프록시에서
적용하며, 최종 추론은 전 조건 동일하게 같은 모델을 호출합니다.

> **요지.** 압축 강도를 높일수록 정확도가 떨어졌고, 정확도를 유지한 구간에서는
> 토큰이 줄지 않았습니다. 컨텍스트가 손상되면 에이전트가 재탐색하면서 호출이
> 늘어, 절감분이 상쇄되기 때문입니다. 자세한 수치와 한계는 위 문서에
> 있습니다.

측정을 재현하거나 조건을 바꿔 돌리시려면
[`labs/agentic-eval`](labs/agentic-eval/) 을 보십시오.

### 종단 측정 결과 — Terminal Bench 2.1

위 표는 **압축기가 문자열을 얼마나 지키나**를 봅니다. 이건 다른 질문입니다 —
**압축된 프롬프트로 에이전트가 과제를 실제로 끝내나.** 공식 러너(`pier`) +
Docker 로 태스크 11종을 en·ko 각각 돌린 결과입니다(110 trial).

| 조건 | en pass@1 | en 기준차 | en 토큰 | ko pass@1 | ko 기준차 | ko 토큰 |
|---|---|---|---|---|---|---|
| 압축 없음 | 54.5% | 기준 | 기준 | 72.7% | 기준 | 기준 |
| `rate 0.9` | 70.0% | +15.5%p | −10.0% | 54.5% | −18.2%p | −34.5% |
| `rate 0.8` | 45.5% | −9.1%p | −20.6% | 54.5% | −18.2%p | −40.7% |
| `rate 0.7` | 45.5% | −9.1%p | −13.9% | 54.5% | −18.2%p | −34.0% |
| **`rate 0.5`** | 30.0% | **−24.5%p** | −55.4% | 27.3% | **−45.5%p** | −47.9% |

`rate` 는 **남길 비율**이라 값이 작을수록 강하게 압축합니다. 기준차는 각각
**같은 언어의 압축 없음 조건**과 비교한 값입니다.

**두 언어 모두 같은 방향으로 떨어졌습니다.** 다만 압축을 끄고 3회 반복한
측정에서 pass@1 이 ±18.2%p 흔들렸으므로, 그 폭을 넘어선 하락은
`rate 0.5` 에서만 확실합니다. 나머지 구간은 방향은 보이되 크기를 단정할 수
없습니다.

> 컨텍스트가 29배 큰 DeepSWE 에서는 토큰이 27~43% 줄었지만 이슈 해결
> 진척도(f2p)가 60.5% → 22~29% 로 떨어졌고, 호출 한도를 넘겨 과제를
> 끝내지 못한 trial 4건이 **전부 압축 조건**이었습니다. 자세한 내용은
> [`reports/analysis/brief.html`](reports/analysis/) 에 있습니다.

### 읽으실 때 주의할 점

**`04`의 최저 보존율 0%가 눈에 띄실 겁니다.** 평균은 79.2%인데 어떤 케이스는
정답이 통째로 사라졌다는 뜻입니다. 나머지 랩이 100%인 것과 대비됩니다.

**`03`은 절감이 가장 크지만 되돌릴 수 없습니다.** 요약은 원문을 버립니다.
나중에 원문이 필요해질 수 있다면 `02`가 안전합니다.

**같은 랩이라도 설정을 바꾸면 결과가 크게 달라집니다.** `04`는 `rate`를
0.7에서 0.3으로 낮추면 절감이 29% → 65%로 오르는 대신 보존율이 무너집니다.
각 랩 README의 조건 비교표를 함께 보시길 권합니다.

### 절감률과 보존율을 항상 같이 봅니다

이 저장소에서 가장 자주 나오는 이야기입니다.

**절감률**은 토큰이 얼마나 줄었는지이고, **정답 보존율**은 답하는 데 꼭 필요한
문자열이 압축 후에도 남아 있는 비율입니다. 절감률만 크고 보존율이 낮으면
싸게 만들었지만 쓸 수 없는 컨텍스트가 됩니다.

집계할 때는 평균과 함께 **최저값**을 반드시 냅니다. 평균이 90%여도 어느 한
케이스가 0%라면 그 질문에는 아예 답할 수 없는데, 평균은 그 사실을 가려버리기
때문입니다.

### 보존율은 하한입니다

보존율은 문자열 검사라서 뜻이 지켜졌는데 표현이 바뀌면 0%로 셉니다. 그래서
[`compare/qa_eval.py`](compare/)로 **실제로 답할 수 있는지**를 따로 잽니다.

`sample` 12건에서 확인한 결과입니다.

| 조건 | 보존율 | 정답률 |
|---|---|---|
| 요약 (지시 없음) | 33.3% | **58.3%** |
| 요약 (보존 지시) | 88.9% | **91.7%** |

보존율이 실패를 과장하고 있었습니다. 반대로 **보존율 100%인데 답을 못 하는**
경우도 나왔습니다 — 문자열은 남았는데 문장이 잘려 뜻이 성립하지 않은 것입니다.

**보존율로 빠르게 거르고 정답률로 확인하는 순서**를 권합니다.

## 두 가지 평가 축

이 저장소는 서로 다른 두 질문에 답합니다. 같은 라이브러리라도 축이 다르면
파라미터가 달라지는데, 묻는 것이 다르기 때문입니다.

| | `labs/00~06` | [`labs/agentic-eval`](labs/agentic-eval/) |
|---|---|---|
| 무엇을 묻나요 | 압축률 대비 정보 손실 | 압축된 컨텍스트로 **실제 작업을 해내는가** |
| 입력 | `labs/data/` 코퍼스 | Terminal Bench 2.1 · DeepSWE 태스크 |
| 실행 | 파이썬 프로세스 | 공식 러너(`pier`) + Docker 격리 |
| 채점 | 정답 문자열 보존 여부 | 태스크에 포함된 테스트 |
| 지표 | 토큰 수, 정답 보존율 | pass@1, f2p/p2p, 입력 토큰, 스텝 |
| 비용 | 초~분 | 시간~일 (Docker, 유료 API) |

앞쪽 축은 값싸고 빠르게 **명백히 깨진 것**을 걸러냅니다. 뒤쪽 축은 느리고
비싸지만 실전에 가까운 신호를 줍니다. 앞에서 거르고 뒤에서 확인하는 순서로
쓰시면 좋습니다.

> **두 축이 어긋날 수 있습니다.** 압축기가 문자열은 잘 보존하는데 에이전트
> 정확도는 떨어지는 경우가 실제로 관측되었습니다. 손상된 컨텍스트를
> 에이전트가 반복 탐색하면서 호출이 늘고, 그만큼 토큰도 되레 늘어나기
> 때문입니다. 앞쪽 축만 보고 도입을 결정하지 마십시오 —
> [`reports/analysis/brief.html`](reports/analysis/) 에 수치가 있습니다.

## 환경 준비

```bash
git clone git@github.com:hijigoo/token-compression.git
cd token-compression

uv venv && uv pip install -r requirements.txt
./scripts/setup_git.sh            # 커밋 시 노트북 출력을 자동으로 지웁니다
```

API가 필요한 랩(`03` 이후)을 돌리실 때는 자격증명을 넣어주세요. 변수 이름이
탐색 노트북과 같으므로, 이미 만들어 두신 것이 있다면 그대로 복사하셔도 됩니다.

```bash
cd labs && cp .env.example .env
# 또는 이미 쓰시던 것을 그대로
cd labs && cp ../scripts/explore/.env .env
```

랩별 의존성은 `labs/*/requirements.txt`로 나눠 두었습니다. `04-llmlingua`처럼
torch 핀이 걸리는 랩이 다른 랩과 충돌하지 않게 하려는 것입니다.
