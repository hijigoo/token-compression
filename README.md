# token-compression

LLM 컨텍스트 압축 기법을 **같은 조건에서 나란히 비교**하는 실험 저장소입니다.

"이 기법은 몇 % 줄여줍니다" 같은 말은 흔하지만, 무엇을 기준으로 잰 것인지,
줄이면서 무엇을 잃었는지는 잘 드러나지 않습니다. 이 저장소는 그 두 가지를
항상 함께 재도록 만들어 두었습니다.

## 처음 오셨다면

압축을 왜 하는지, 무엇이 어려운지부터 보시는 편이 빠릅니다.

| 순서 | 어디를 보시면 | 무엇을 얻으시나요 |
|---|---|---|
| 1 | [`docs/llm-token-compression-2026.html`](docs/) | 기법 지형도를 한눈에 (브라우저로 열어보세요) |
| 2 | [`labs/00-baseline`](labs/00-baseline/) | 실험 하네스가 어떻게 도는지 |
| 3 | [`labs/01-lossless-structure`](labs/01-lossless-structure/) | 가장 안전한 압축부터 |
| 4 | [`scripts/explore/`](scripts/explore/) | 원리를 손으로 익히는 노트북 5종 |

랩마다 `run.ipynb`가 있습니다. 코드를 읽기 전에 노트북을 먼저 돌려보시면
무엇을 하는 랩인지 훨씬 빨리 감이 잡히실 겁니다.

```bash
cd labs/01-lossless-structure && jupyter lab run.ipynb
```

번호는 **읽는 순서**이자 의존성이 가벼운 순서입니다. 앞쪽 랩은 표준
라이브러리만으로 돌아가고, 뒤로 갈수록 API나 모델 다운로드가 필요해집니다.

> **표의 숫자만 보고 판단하지는 말아 주세요.** 각 랩의 권장 조건 기준이라서,
> 같은 랩이라도 설정을 바꾸면 절감이 커지는 대신 보존율이 0%가 되기도 합니다.
> 랩 README의 조건 비교표를 함께 보시길 권합니다.

### 절감률과 보존율을 항상 같이 봅니다

이 저장소에서 가장 자주 나오는 이야기입니다.

**절감률**은 토큰이 얼마나 줄었는지이고, **정답 보존율**은 답하는 데 꼭 필요한
문자열이 압축 후에도 남아 있는 비율입니다. 절감률만 크고 보존율이 낮으면
싸게 만들었지만 쓸 수 없는 컨텍스트가 됩니다.

집계할 때는 평균과 함께 **최저값**을 반드시 냅니다. 평균이 90%여도 어느 한
케이스가 0%라면 그 질문에는 아예 답할 수 없는데, 평균은 그 사실을 가려버리기
때문입니다.

### 보존율은 하한입니다

보존율은 문자열 검사라서 뜻이 지켜졌는데 표현이 바뀌면 0%로 셉니다. 그래서
[`compare/qa_eval.py`](compare/)로 **실제로 답할 수 있는지**를 따로 잽니다.

`sample` 12건에서 확인한 결과입니다.

| 조건 | 보존율 | 정답률 |
|---|---|---|
| 요약 (지시 없음) | 33.3% | **58.3%** |
| 요약 (보존 지시) | 88.9% | **91.7%** |

보존율이 실패를 과장하고 있었습니다. 반대로 **보존율 100%인데 답을 못 하는**
경우도 나왔습니다 — 문자열은 남았는데 문장이 잘려 뜻이 성립하지 않은 것입니다.

**보존율로 빠르게 거르고 정답률로 확인하는 순서**를 권합니다.

## 설계 원칙 세 가지

지키다 보면 불편할 때도 있지만, 각각 이유가 있어서 두었습니다.

### 1. 랩끼리는 서로를 import 하지 않습니다

랩 하나를 고쳤을 때 다른 랩이 조용히 따라 바뀌는 상황을 막으려는 것입니다.
예를 들어 `agentic-eval`은 `05-headroom`을 import하지 않고, Headroom을 별도
프로세스로 띄운 다음 URL로만 이야기합니다.

다만 [`labs/kit`](labs/kit/)은 예외입니다. 랩 → kit 단방향이라 순환이 생기지
않고, 지표 코드가 랩마다 갈라지는 편이 훨씬 위험하기 때문입니다. 자세한 사정은
kit README에 적어 두었습니다.

### 2. 폴더를 늘리지 않습니다

라이브러리를 추가하실 때는 파일 하나, 실험을 추가하실 때는 yaml 하나면
충분하도록 만들어 두었습니다. 폴더가 늘어나면 어디를 봐야 할지 알기
어려워집니다.

### 3. 비교 가능성을 가장 앞에 둡니다

같은 입력, 같은 시드, 같은 측정 방식이 아니면 숫자를 나란히 놓을 수 없습니다.
그래서 실행할 때마다 kit 버전과 토큰 측정 방식을 결과에 함께 기록합니다.

## 두 가지 평가 축

이 저장소는 서로 다른 두 질문에 답합니다. 같은 라이브러리라도 축이 다르면
파라미터가 달라지는데, 묻는 것이 다르기 때문입니다.

| | `labs/00~06` | [`labs/agentic-eval`](labs/agentic-eval/) |
|---|---|---|
| 무엇을 묻나요 | 압축률 대비 정보 손실 | 압축된 컨텍스트로 **실제 작업을 해내는가** |
| 입력 | `labs/data/` 코퍼스 | DeepSWE 태스크 (컨테이너 런타임) |
| 지표 | 토큰 수, 정답 보존율 | pass@1, 입력 토큰 |
| 비용 | 초~분 | 시간~일 (Docker, 유료 API) |

앞쪽 축은 값싸고 빠르게 **명백히 깨진 것**을 걸러냅니다. 뒤쪽 축은 느리고
비싸지만 실전에 가까운 신호를 줍니다. 앞에서 거르고 뒤에서 확인하는 순서로
쓰시면 좋습니다.

## 환경 준비

```bash
git clone git@github.com:hijigoo/token-compression.git
cd token-compression

uv venv && uv pip install -r requirements.txt
./scripts/setup_git.sh            # 노트북 출력 자동 제거 (아래에서 설명드립니다)
```

API가 필요한 랩(`03` 이후)을 돌리실 때는 자격증명을 넣어주세요. 변수 이름이
탐색 노트북과 같으므로, 이미 만들어 두신 것이 있다면 그대로 복사하셔도 됩니다.

```bash
cd labs && cp .env.example .env
# 또는 이미 쓰시던 것을 그대로
cd labs && cp ../scripts/explore/.env .env
```

랩별 의존성은 `labs/*/requirements.txt`로 나눠 두었습니다. `04-llmlingua`처럼
torch 핀이 걸리는 랩이 다른 랩과 충돌하지 않게 하려는 것입니다.

## 노트북을 커밋하기 전에

노트북 실행 결과에는 리소스 이름이나 응답 본문이 남기 쉽습니다. 그래서 push
직전에 출력을 자동으로 비우도록 해 두었습니다.

```bash
./scripts/setup_git.sh
```

이 스크립트는 두 겹으로 막습니다.

- **clean 필터** — `git add` 시점에 노트북 출력을 제거합니다
- **pre-push 훅** — 그래도 남아 있으면 push를 멈춰 세웁니다

훅이 막아섰다면 아래로 정리하신 뒤 다시 커밋해 주세요.

```bash
python scripts/strip_outputs.py labs/**/run.ipynb
```

> 예전에 이 훅이 **아무것도 검사하지 않으면서 통과만 하던** 적이 있었습니다.
> 검사 코드를 고치셨다면 일부러 출력이 남은 노트북으로 한 번 막히는지
> 확인해 보시길 권합니다.

## 자주 겪는 문제

### `AttributeError: ... object has no attribute ...`

노트북을 **켜 둔 채로** 저장소를 갱신하셨을 때 나옵니다. 파일은 새것인데
커널 메모리에는 예전 모듈이 남아 있어서 생기는 일입니다. 코드 문제가
아니니 당황하지 않으셔도 됩니다.

노트북을 다시 열고 **1번 셀을 실행**해 주세요. 1번 셀이 예전 모듈을 지우고
새로 읽습니다. 지웠을 때는 아래 줄이 함께 찍힙니다.

```
모듈 2개를 새로 읽었습니다 — 커널에 남아 있던 예전 코드를 지웠습니다
```

그래도 안 되시면 커널을 재시작해 주세요.

### `requires the ipykernel package`

`uv`로 만든 가상환경에는 `ipykernel`이 기본으로 들어가지 않습니다.
랩 전용 환경을 쓰는 [`04-llmlingua`](labs/04-llmlingua/)에서 주로 만나십니다.

```bash
cd labs/04-llmlingua
uv pip install --python .venv/bin/python ipykernel
```

설치 후 VS Code에서 **커널을 다시 선택**해 주세요.

### `jsonl 을 찾지 못했습니다`

코퍼스를 아직 안 만드신 경우입니다.

```bash
cd labs/data && python make_synthetic.py    # 한국어 3종
cd labs/data && python make_bilingual.py    # 한·영 이중언어
```

### `AZURE_OPENAI_ENDPOINT 가 없습니다`

API를 쓰는 조건을 돌리셨는데 `.env`가 없는 경우입니다.

```bash
cd labs && cp .env.example .env
```

네트워크 없이 돌리시려면 설정의 `tokenizer.mode`를 `local`로 바꾸시면 됩니다.
