# 03-summarize-llm — 모델에게 요약시키기

> **한 줄 요약** — 같은 모델, 같은 문서, 같은 목표 길이인데 프롬프트만 바꿨더니
> 보존율이 **33.3% → 88.9%** 가 됐습니다. 그러면서 절감도 **더 커졌습니다.**

## 앞의 두 랩과 무엇이 다른가요

| | 정보는 | 되돌리기 | 의존성 |
|---|---|---|---|
| [`01-lossless-structure`](../01-lossless-structure/) | 아무것도 안 버립니다 | 가능 | 없음 |
| [`02-handle-ref`](../02-handle-ref/) | 밖에 두고 핸들만 | 꺼내면 원문 | 없음 |
| **`03-summarize-llm`** | **버립니다** | **불가** | **API** |

버리는 만큼 많이 줄어듭니다. 문제는 **무엇을 버렸는지 알기 어렵다**는 것입니다.
요약 모델은 "결제금액의 12%"를 "일정 비율"로 바꾸는 것을 요약이라고 생각합니다.
사람이 읽기에는 자연스럽지만, 그 숫자로 답해야 하는 질문에는 쓸 수 없습니다.

## 시작하기

먼저 자격증명을 넣어주세요. 변수 이름이 탐색 노트북과 같으니, 이미 만들어
두신 것이 있다면 그대로 복사하셔도 됩니다.

```bash
cd labs && cp .env.example .env      # 또는 cp ../scripts/explore/.env .env
```

노트북으로 보시는 편이 이해가 빠릅니다. 프롬프트 세 가지를 나란히 보여드리고,
**돌리기 전에 예상 API 호출 수를 먼저 알려드립니다.**

```bash
cd 03-summarize-llm && jupyter lab run.ipynb
```

명령줄로 돌리실 때는 `--limit`으로 조금만 먼저 확인해 보시길 권합니다.

```bash
python compress.py configs/preserve.yaml --limit 2    # 먼저 2건만
python compress.py configs/preserve.yaml
```

> **이 랩만 유료입니다.** 케이스 N건이면 요약 호출이 N회 나갑니다. 같은
> 프롬프트는 디스크에 캐시되므로 두 번째 실행부터는 0회입니다.
> 실수로 큰 코퍼스를 돌리셨을 때를 대비해 `--max-calls`로 상한도 걸어
> 두었습니다(기본 200).

## 프롬프트 세 가지

이 랩에서 압축률을 정하는 것은 알고리즘이 아니라 **무엇을 지키라고 말했는지**
입니다. 세 가지를 나란히 두고 무엇이 달라지는지 보실 수 있게 했습니다.

| 스타일 | 무엇을 알려주나 |
|---|---|
| `plain` | 그냥 요약하라고만 합니다 |
| `question_aware` | 질문을 알려주고 그에 필요한 것을 남기라고 합니다 |
| `preserve` | 숫자·식별자·부정어를 **글자 그대로** 남기라고 못 박습니다 |

## 결과 ①: 장문 (`sample-long` 8건, 3,749토큰)

| 스타일 | 절감 | 평균 보존율 | **최저 보존율** | 온전한 케이스 |
|---|---|---|---|---|
| `plain` | 78.5% | 87.5% | **50.0%** | 75% |
| `question_aware` | **89.2%** | 100% | **100%** | 100% |
| `preserve` | 86.5% | 100% | **100%** | 100% |

**질문을 알려주는 것만으로 절감이 10.7%p 오르고 보존율도 100%가 됩니다.**
무엇을 남길지 판단할 근거가 생기면 나머지를 과감히 버릴 수 있기 때문입니다.
근거가 없으면 모델은 "골고루 조금씩" 남기고, 그 결과 정답도 반쪽만 남습니다.

### `plain`이 무엇을 잃었는지 보시면

```
lg-004  원문 … 60분 내에 복구되지 않으면 L3-platform 으로 에스컬레이션합니다.
        plain … 60분 미복구 시 에스컬레이션,          ← L3-platform 이 사라짐
        preserve … 60분 내에 복구되지 않으면 L3-platform 으로 에스컬레이션합니다.
```

문장은 매끄럽게 읽힙니다. 그런데 "누구에게 에스컬레이션하나요?"라는 질문에는
답할 수 없게 됐습니다.

**식별자가 자연스러운 표현 속으로 녹아 없어지는 것**이 요약의 대표적인 실패
방식입니다. 읽어서는 티가 나지 않기 때문에 오히려 더 위험합니다.

## 결과 ②: 짧은 산문 (`sample` 12건) — 여기가 훨씬 어렵습니다

| 스타일 | 절감 | 평균 보존율 | **최저 보존율** | 온전한 케이스 |
|---|---|---|---|---|
| `plain` | 66.9% | **33.3%** | **0.0%** | 16.7% |
| `preserve` | **71.9%** | **88.9%** | 33.3% | 75% |

`plain`은 12건 중 **10건이 깨졌습니다.** 그리고 `preserve`는 **더 많이 줄이면서
더 많이 지켰습니다.**

압축률과 보존율이 반드시 맞바꿔야 하는 관계는 아니라는 뜻입니다. 무엇을 버려도
되는지 알면 둘 다 좋아집니다.

### 실제로 사라진 것들 (`plain`)

| 케이스 | 원문 | 요약 | 무슨 일이 |
|---|---|---|---|
| `doc-002` | `32,450,000원` | `3,245만원` | 단위를 바꿔 **정확한 금액이 소실** |
| `doc-006` | `A-1001 … A-1004` | `주문 4건` | **식별자 전멸** |
| `doc-008` | 지사별 담당자·전화번호 | `담당 팀장과 연락처 안내` | **내용이 통째로** |
| `doc-009` | 엔드포인트별 지연·오류율 표 | `임베드가 QPS 최고…` | 표가 **감상평으로** |
| `doc-010` | 주문 JSON 4건 | `총액은 10만2천 원입니다` | 원본 레코드 소멸 |

`doc-008`이 특히 인상적입니다. 요약문이 **"연락처 안내"라고 말만 하고 정작
연락처를 담지 않았습니다.** 목차를 요약이라고 내놓은 셈입니다.

### 유형별 — 어디가 먼저 무너지나

| 유형 | `plain` 최저 | `preserve` 최저 | |
|---|---|---|---|
| `structured` | 0% | 66.7% | 표·JSON은 서술로 바뀌면 끝입니다 |
| `identifier` | 0% | 66.7% | 코드·번호는 "몇 건"으로 뭉개집니다 |
| `similar` | 0% | 100% | 비슷한 항목이 하나로 합쳐집니다 |
| `negation` | 0% | 33.3% | **부정어가 가장 안 지켜집니다** |
| `numeric` | 0% | 100% | 지시하면 잘 지킵니다 |
| `short` | 50% | 100% | 짧으면 요약할 것도 없습니다 |

**부정어는 지시해도 잘 지켜지지 않습니다.** `preserve`에서도 최저 33.3%입니다.
"접수되지 않습니다"가 "제외"로 바뀌는 식인데, 뜻은 같아도 원문 문자열은
사라집니다.

부정이 뒤집히면 답이 정반대가 되기 때문에 가장 조심하셔야 할 유형입니다.

## 이 지표가 놓치는 것도 알아두세요

보존율은 **문자열 일치**로 잽니다. LLM 호출이 없어 스윕이 공짜라는 장점이
있지만, 대가가 있습니다.

```
원문   주말 및 공휴일에는 접수되지 않습니다      must_include: ["않습니다"]
요약   주말·공휴일 제외                        → 보존율 0%
```

**뜻은 지켜졌는데 0%로 셉니다.** 반대로 숫자를 그대로 베끼면서 문맥을 뒤집는
요약은 100%로 셉니다.

즉 이 지표는 **하한**으로 보시는 것이 맞습니다. 낮으면 확실히 문제가 있지만,
높다고 해서 안전하다는 뜻은 아닙니다.

의미 수준의 평가는 `agentic-eval` 축에서 할 일입니다. 여기서는 값싸고 빠르게
**명백히 깨진 것**을 걸러내는 데 집중합니다.

## 자가 점검

보존율이 낮아도 실패로 치지 않습니다. **그게 이 랩의 관찰 대상**이기 때문입니다.
대신 다음을 봅니다.

| 점검 | 왜 |
|---|---|
| 빈 요약 | 추론 모델이 `max_output_tokens`를 다 써서 빈 본문을 돌려주면, 절감률 100%라는 엉터리 결과가 나옵니다 → **exit 1** |
| 원문보다 길어짐 | 짧은 글은 요약할 게 없습니다 → 메모로 남김 |

> `kit.provider.complete()`가 빈 본문에서 예외를 냅니다. 조용히 빈 문자열을
> 반환했다면 "83% 절감!" 같은 결과를 그대로 믿었을 것입니다.

## 설정

| 파라미터 | 뜻 | 기본 |
|---|---|---|
| `style` | `plain` / `question_aware` / `preserve` | `preserve` |
| `target_ratio` | 목표 길이 = 원문 × 이 값 (글자 수로 지시) | `0.4` |
| `cache` | 같은 프롬프트를 다시 안 부릅니다 | `true` |
| `max_calls` | API 호출 상한 | `200` |
| `max_output_tokens` | 추론 모델은 생각하는 데도 출력 토큰을 씁니다 | `2048` |

목표 길이를 **토큰이 아니라 글자 수**로 주는 이유는 모델이 자기 토큰을
세지 못하기 때문입니다.

> **캐시 키에 프롬프트 전문이 들어갑니다.** 원문으로만 잡으면 스타일이나
> 목표 길이를 바꿔도 **조용히 옛 결과**가 나옵니다. 설정을 바꿨는데 숫자가
> 안 변하면 대개 이 실수입니다.
