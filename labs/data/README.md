# labs/data — 공유 입력 코퍼스

`labs/00~06`이 **똑같은 입력**으로 비교되도록 모아둔 곳입니다.
서로 다른 텍스트로 잰 압축률은 나란히 놓을 수 없기 때문에, 이 폴더는
사실상 모든 실험의 전제조건입니다.

## 먼저 코퍼스를 만들어 주세요

```bash
cd labs/data && python make_synthetic.py
```

전부 합성 데이터입니다. 실제 고객 데이터가 섞일 여지가 없도록 스크립트로
찍어내는 방식을 택했습니다. 스크립트 자체가 획득 절차라서 언제든 똑같이
다시 만들 수 있습니다.

| 코퍼스 | 구성 | 주로 쓰는 랩 |
|---|---|---|
| `sample` | 짧은 산문 12건. 숫자·부정어·식별자가 밀집 | 전 랩 |
| `sample-structured` | JSON·로그·키값·표·XML 12건 | `01-lossless-structure` |
| `sample-long` | 7개 절로 나뉜 장문 8건 | `02-handle-ref`, `03-summarize-llm` |

### 코퍼스마다 노리는 것이 다릅니다

**`sample`** 은 짧지만 어렵습니다. 유형 6종(`numeric`·`negation`·`identifier`·
`similar`·`structured`·`short`)이 각 2건씩 들어 있는데, 전부 압축이 잘 깨지는
자리입니다. 어느 유형이 먼저 무너지는지 보시려고 나눠 두었습니다.

**`sample-structured`** 에는 무손실 변환이 먹고 사는 "표현의 중복"이 들어
있습니다. 반복되는 키 이름, 줄마다 붙는 타임스탬프, 정렬용 공백 같은 것들입니다.
산문에는 이런 중복이 없어서 같은 코드가 아무 일도 하지 못하는데, 그 대비를
보시라고 따로 두었습니다.

**`sample-long`** 은 정답이 **한 절에만** 들어 있고 그 위치가 문서마다
다릅니다. 정답이 항상 앞에 있으면 "앞에서 잘라내기"만으로도 통과해 버려서
라우팅 품질을 평가할 수가 없습니다. 위치를 흩어 놓은 이유가 그것입니다.

## 코퍼스는 한 번 넣으면 바꾸지 않습니다

**이미 있는 파일을 수정하지 말아주세요.**

내용이 바뀌면 과거 `runs/` 결과와의 비교가 깨지는데, 이 고장은 **아무 에러 없이
조용히** 일어납니다. 두 달 전 숫자와 오늘 숫자가 왜 다른지 영영 알 수 없게
됩니다.

바꿔야 하실 때는 수정 대신 새로 추가해 주세요.

```
docs-long/      →  docs-long-v2/     (기존 것은 그대로 둡니다)
```

## 데이터 파일을 커밋하지 않는 이유

용량 문제도 있지만, 더 큰 이유는 **고객 데이터가 섞일 수 있어서**입니다.
`.gitignore`가 `labs/data/**`를 제외하고 `README.md`·`fetch.sh`·`manifest.json`
같은 메타 파일만 남깁니다.

다만 `sample*` 코퍼스는 예외로 커밋합니다. 합성 데이터라 안전하고, 저장소를
받자마자 아무 준비 없이 랩을 돌려보실 수 있는 편이 낫다고 판단했습니다.

## 코퍼스 형식

한 줄이 한 케이스인 jsonl입니다.

```json
{"id": "doc-001",
 "text": "압축 대상 원문 …",
 "question": "이 문서에서 환불 수수료는?",
 "must_include": ["10%", "않습니다"],
 "meta": {"kind": "numeric"}}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `text` | 필수 | 압축할 원문입니다 |
| `id` | 선택 | 없으면 파일명과 줄 번호로 자동 생성됩니다 |
| `question` | 선택 | 질문 기반 압축(`02`, `03`)에서 씁니다 |
| `must_include` | 선택 | **정답에 꼭 필요한 문자열**입니다 |
| `meta.kind` | 선택 | 집계를 유형별로 쪼갤 때 씁니다 |

`must_include`가 이 저장소에서 가장 중요한 필드입니다. 이게 있어야 정답
보존율을 잴 수 있고, LLM 호출이 없어서 압축률 스윕을 수백 번 돌려도 비용이
들지 않습니다.

넣으실 때는 **답에 반드시 필요한 최소한의 문자열**을 고르시면 좋습니다.
금액이 답이면 `"32,450,000"`처럼 숫자 자체를, 부정이 핵심이면 `"않습니다"`처럼
부정어를 넣습니다. 문장 전체를 넣으시면 표현만 살짝 바뀌어도 0%가 나옵니다.

## 코퍼스를 새로 추가하실 때

각 코퍼스 폴더에는 `manifest.json`이 **반드시** 있어야 합니다. 출처와 리비전이
없으면 나중에 재현할 방법이 없기 때문입니다.

```json
{
  "name": "docs-long",
  "source": "https://huggingface.co/datasets/...",
  "revision": "a1b2c3d",
  "license": "CC-BY-4.0",
  "n_samples": 200,
  "added_at": "2026-08-28",
  "note": "평균 12k 토큰. 8k 미만 샘플은 제외했습니다."
}
```

절차는 이렇습니다.

1. `fetch.sh`에 획득 로직을 추가합니다 — 수동 복사 대신 스크립트로 만들어
   주세요. 재현이 가능해야 합니다
2. `manifest.json`을 작성합니다
3. `./fetch.sh <코퍼스명>`으로 확인합니다

합성 코퍼스라면 `make_synthetic.py`에 생성 함수를 더하시는 편이 간단합니다.

### 새 코퍼스는 baseline으로 먼저 확인해 보세요

```bash
cd labs/00-baseline
python compress.py configs/noop.yaml --data ../data/<새-코퍼스>
```

압축을 하지 않는 랩이므로 **절감 0% · 최저 보존율 100%**가 나와야 정상입니다.
여기서 어긋난다면 압축기가 아니라 코퍼스나 `must_include` 쪽에 문제가 있다는
신호입니다.
