# 04-llmlingua — 작은 모델이 토큰을 골라 버립니다

> **한 줄 요약** — 세 변형 중 **LLMLingua-2만 쓸 만했습니다.** 그리고 같은
> 설정에서 **한국어가 영어보다 먼저 무너집니다.**

## 앞선 랩들과 무엇이 다른가요

| 랩 | 누가 판단하나 | 언어 영향 |
|---|---|---|
| [`01`](../01-lossless-structure/) 무손실 | 규칙 | 없음 |
| [`02`](../02-handle-ref/) 참조핸들 | 겹침 점수 | 적음 |
| [`03`](../03-summarize-llm/) 요약 | **큰 모델**이 다시 씁니다 | 적음 |
| **`04`** 프루닝 | **작은 모델**이 토큰마다 판정합니다 | **큽니다** |

중요도를 매기는 모델이 작기 때문에, 그 모델이 약한 언어에서는 성능이
떨어집니다. 그래서 이 랩만 **한·영 이중언어 코퍼스**를 씁니다.

## 세 형제

같은 `PromptCompressor` 클래스에 파라미터만 다릅니다. 그래서 폴더를 나누지
않고 설정으로 가릅니다.

| 변형 | 무엇이 다른가 | 필요한 것 |
|---|---|---|
| `v1` LLMLingua | 토큰별 정보량으로 프루닝 | 인과 LM |
| `long` LongLLMLingua | **질문**을 주고 문단별 중요도를 함께 봄 | 인과 LM + 질문 |
| `v2` LLMLingua-2 | 분류 모델이 토큰을 남길지 판정 | 전용 인코더 |

## 시작하기

의존성이 무거워서 랩 전용 가상환경으로 격리합니다.

```bash
cd labs/04-llmlingua
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

.venv/bin/python compress.py configs/v2.yaml
.venv/bin/python compress.py configs/v2.yaml --sweep 0.9,0.7,0.5,0.3
```

**처음 실행은 모델을 내려받습니다** — `v2`는 약 700MB, `v1`/`long`은 약 1GB
입니다. `~/.cache/huggingface/`에 남아 다음부터는 로딩만 합니다.

노트북도 있습니다.

```bash
jupyter lab run.ipynb
```

## 결과 — `sample-bilingual` 12건 (한·영 6쌍)

### ① 변형 비교 (`rate=0.5`)

| 변형 | 절감 | 보존율 | 한국어 | 영어 |
|---|---|---|---|---|
| `v1` | 16.4% | 70.8% | 66.7% | 75.0% |
| `long` | 48.9% | **41.7%** | 58.3% | **25.0%** |
| **`v2`** | **46.3%** | **70.8%** | 58.3% | **83.3%** |

**`v2`가 유일하게 쓸 만합니다.** `long`은 가장 많이 줄였지만 보존율이 절반도
안 됩니다. 질문까지 주는데도 결과가 가장 나쁜 이유는 아래에서 설명합니다.

### ② 압축률 스윕 (`v2`) — 한국어가 먼저 무너집니다

| `rate` | 절감 | 보존율 | **한국어** | **영어** |
|---|---|---|---|---|
| 0.9 | 7.5% | 95.8% | 100% | 91.7% |
| 0.7 | 27.2% | 79.2% | **66.7%** | **91.7%** |
| 0.5 | 46.3% | 70.8% | 58.3% | 83.3% |
| 0.3 | 64.8% | 54.2% | 50.0% | 58.3% |

`rate=0.7`을 보세요. 영어는 아직 91.7%인데 **한국어는 이미 66.7%로 떨어졌습니다.**
같은 설정, 같은 내용인데 언어가 다릅니다.

> `rate`는 **남길 비율**입니다. 공식 문서에 `ratio`로 적힌 곳이 있는데
> 실제 인자명은 `rate`입니다. `target_token`을 함께 주면 `rate`를 덮어씁니다.

### ③ 한국어는 애초에 토큰을 더 씁니다

| | 문자 | 토큰 | 문자당 |
|---|---|---|---|
| 한국어 | 1,702자 | 918 | 0.54 |
| 영어 | 3,272자 | 958 | 0.29 |

**같은 내용에 한국어가 문자당 1.8배**를 씁니다(`o200k_base` 기준). 압축이
더 절실한 쪽인데 압축 품질은 더 나쁩니다.

## 왜 `v1`/`long`이 나쁜가 — 정직하게

**모델 크기 때문입니다.** 논문은 Llama-2-7B를 썼는데 이 랩은 `Qwen2.5-0.5B`를
씁니다. 13GB를 받게 하고 싶지 않았습니다.

작은 모델로 토큰 단위 프루닝을 하면 이렇게 됩니다.

```
원문        the total amount charged was 32,450,000 KRW. Of that, 1,280,500 …
long r=0.5  the total amount charged was 32.  Of0 was, Com to February the7
long r=0.9  the total amount charged was 32,450,00RW.  Of that, 1,28
                                         ↑ 숫자 중간이 잘립니다
```

`rate=0.9`(10%만 버림)에서도 `32,450,000 KRW`가 `32,450,00RW`가 됩니다.
**토큰 단위로 자르기 때문에 숫자와 식별자가 조각납니다.**

`v2`가 안전한 이유는 분류 모델이 단어에 가까운 단위로 판정해서 숫자를 통째로
남기기 때문입니다.

> **결론을 일반화하지 마세요.** "LongLLMLingua가 나쁘다"가 아니라
> **"작은 순위 모델로는 못 쓴다"**입니다. 7B급을 쓰실 수 있으면 결과가
> 달라질 수 있습니다. `configs/*.yaml`의 `model_name`으로 바꾸실 수 있습니다.

## `v2`도 원문을 그대로 두지 않습니다

`rate=1.0`은 아무것도 버리지 않는다는 뜻인데, 돌려보면 **토큰이 늘어납니다.**

```bash
python compress.py configs/v2-noop.yaml
# → 절감 -3.3% · 보존율 100%
```

```
전  총 결제 건수는 1,284건이며 결제 총액은 32,450,000원입니다 … 3.9%에
후  총 결제 건수는 1, 284건이며 결제 총액은 32, 450, 000원입니다 … 3. 9 % 에
```

토큰에서 텍스트를 다시 만들기 때문에 쉼표와 기호 주변이 벌어집니다.
**숫자가 많은 짧은 글에서는 압축이 오히려 손해**입니다.

정보는 남아 있어서 보존율은 100%입니다. `kit`의 보존율 계산이 쉼표·공백을
지우고 비교하기 때문입니다. 그래서 이 랩의 자가 점검은 토큰이 아니라
**보존율**을 봅니다.

## 조용히 무시되는 인자를 막았습니다

이 랩에서 가장 조심할 부분입니다. `use_llmlingua2=True`인 압축기에
`question`이나 `rank_method`를 넘기면 **에러 없이 무시됩니다.**
LongLLMLingua 설정을 v2에 잘못 붙여도 그냥 돌아가고 결과만 v2 그대로입니다.

숫자가 안 바뀌는 이유를 찾느라 시간을 버리기 쉬워서, 어댑터가 거부합니다.

```
variant=v2 이 쓰지 않는 인자입니다: ['question', 'rank_method']
  LongLLMLingua 전용 인자로 보입니다. v2 는 질문을 쓰지 않습니다 —
  variant 를 long 으로 바꾸시거나 이 인자를 빼주세요.
```

케이스를 다 돌린 뒤가 아니라 **설정을 읽자마자** 확인합니다.

## 설정

| 파라미터 | 뜻 | 기본 |
|---|---|---|
| `variant` | `v1` / `long` / `v2` | `v2` |
| `rate` | **남길** 비율 | `0.5` |
| `model_name` | 순위 모델을 바꿉니다 | 변형별 기본값 |
| `force_reserve_digit` | 숫자를 지키려 시도합니다 | `false` |
| `force_tokens` | 항상 남길 토큰 | `[]` |
| `target_token` | 목표 토큰 수. **`rate`를 덮어씁니다** | `-1` |

`long`은 `rank_method`와 `condition_compare`를 어댑터가 기본으로 켭니다.
질문 기반 재순위가 이 변형의 핵심이기 때문입니다.

## 알아두시면 좋은 한계

- **작은 모델로 돌립니다.** 논문 수준 결과를 보시려면 7B급이 필요합니다.
- 코퍼스가 12건으로 작습니다. 경향을 보는 용도이지 벤치마크가 아닙니다.
- `v2`의 다국어 모델은 MeetingBank(회의록)로 학습됐습니다. 문서 성격이
  다르면 결과가 달라질 수 있습니다.
- 보존율은 문자열 검사라 하한입니다. 실제 정답률은
  [`compare/qa_eval.py`](../../compare/)로 재실 수 있습니다.

## 언제 쓰시면 좋을까요

| 상황 | 판단 |
|---|---|
| 영어 장문, 중간 압축(rate 0.7 이상) | **적합** — `v2` |
| 한국어 | **주의** — 같은 rate에서 영어보다 먼저 깨집니다 |
| 숫자·식별자가 답인 문서 | **부적합** — 서식이 깨집니다 |
| 짧은 글 | **부적합** — 오히려 늘어날 수 있습니다 |
| 표·JSON | **부적합** — [`01`](../01-lossless-structure/)이 무손실로 처리합니다 |
