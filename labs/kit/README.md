# labs/kit — 랩 공통 기반

`labs/00~06`이 **같은 방식으로 재고 같은 모양으로 기록**하도록 도와주는
공용 모듈입니다. 랩을 새로 만드실 때 토큰 계산이나 결과 저장을 다시
구현하실 필요가 없습니다.

## 왜 복사하지 않고 공유하나요

저장소 원칙 1번은 "랩끼리 import 하지 않는다"입니다. 그런데 kit은 그 예외로
두었는데, 이유를 설명드리면 이렇습니다.

원칙 1번이 막으려는 것은 **랩과 랩 사이의 얽힘**입니다. `agentic-eval`이
`05-headroom`을 직접 부르면 한쪽을 고칠 때 다른 쪽이 따라 흔들립니다.
kit은 랩 사이가 아니라 **랩 → 기반 단방향**이라서 그런 순환이 생기지 않습니다.

반대로 지표 코드를 랩마다 복사해 두면 시간이 지나면서 조금씩 갈라집니다.
압축률을 문자 수로 재는 랩과 토큰으로 재는 랩이 섞이는 순간, 두 랩의 숫자는
**아무 에러 없이 조용히** 비교 불가능해집니다. 이런 종류의 고장은 발견하기가
정말 어렵습니다. 그래서 원칙 3번(비교 가능성 최우선)을 무의존보다 앞에
두기로 했습니다.

## 재현성은 버전으로 지킵니다

지표 정의가 바뀌면 과거에 뽑아 둔 숫자와 비교가 깨집니다. 이걸 막으려고
실행할 때마다 kit 버전을 `config.snapshot.yaml`에 함께 적습니다.
나중에 결과를 다시 보실 때 "이 실험은 kit 0.1.0으로 쟀구나"를 알 수 있습니다.

지표 계산 방식을 바꾸실 때는 `VERSION`을 꼭 올려주세요.

## 구성

| 파일 | 하는 일 |
|---|---|
| `tokens.py` | 토큰 계산의 단일 진입점. `local`(tiktoken)과 `api`(실측)를 고를 수 있습니다 |
| `provider.py` | Azure OpenAI 호출. 토큰 실측과 텍스트 생성 두 가지를 제공합니다 |
| `dataset.py` | 코퍼스 jsonl 로더 |
| `metrics.py` | 압축률·정답 보존율 계산과 집계 |
| `runner.py` | `runs/<랩>/<설정>/<시각>/`에 결과 4종 기록 |
| `config.py` | yaml 로드 + kit 버전 스탬프 |
| `env.py` | `.env` 탐색과 로드 |
| `display.py` | 표 출력 (노트북에서는 HTML, 터미널에서는 텍스트) |

## 토큰을 어떻게 셀지 고르실 수 있습니다

같은 텍스트라도 재는 방법에 따라 숫자가 다릅니다. 설정에서 고르시면 됩니다.

| | `local` (기본) | `api` |
|---|---|---|
| 방법 | tiktoken, 없으면 문자 기반 근사 | 모델을 호출해 `usage.input_tokens`를 읽습니다 |
| 비용 | 0 | 텍스트마다 호출 1회 |
| 정확도 | 근사치 | **과금 기준 그대로** |
| 포함되는 것 | 텍스트만 | 텍스트 + 메시지 포맷 오버헤드 (실측 +6) |

```yaml
tokenizer:
  mode: api            # local | api
  deployment:          # 비우면 .env 의 AZURE_OPENAI_DEPLOYMENT 를 씁니다
  cache: true          # 같은 텍스트는 한 번만 호출합니다
```

`api`를 쓰실 때는 **캐시를 끄지 말아주세요.** 케이스 N건이면 압축 전후로
2N회를 부르고, 압축률 스윕을 10단계 돌리면 그만큼 곱해집니다. 결과는
`kit/.cache/`에 남아서 다음 실행부터 재사용됩니다(커밋 제외).

> **두 방식의 값을 나란히 놓지 말아주세요.** `api` 값에는 메시지 포맷
> 오버헤드가 포함되어 `local`보다 일관되게 큽니다. 압축 전후를 같은 방식으로
> 재기 때문에 **절감률 비교는 안전하지만**, 절대 토큰 수는 다릅니다.
> 그래서 모든 결과에 `token_backend`를 기록해 둡니다.

## `.env`는 어디서 찾나요

아래 순서로 찾고, **가장 먼저 발견한 것 하나만** 씁니다.

```
labs/.env  →  저장소 루트 .env  →  scripts/explore/.env
```

변수 이름은 `scripts/explore/.env.example`과 같습니다. 노트북용으로 이미
만들어 두신 것이 있다면 그대로 복사해 쓰셔도 됩니다.

셸에 이미 설정된 환경변수는 덮어쓰지 않습니다. CI나 터미널에서 준 값이
항상 우선합니다.

## 랩이 지켜야 할 계약

랩을 새로 만드실 때 아래 두 가지만 맞춰주시면 나머지는 kit이 처리합니다.

**첫째, 실행 방법이 같아야 합니다.**

```bash
python compress.py configs/<이름>.yaml [--data ../data/<코퍼스>] [--out ../../runs]
```

**둘째, 압축 함수의 모양이 같아야 합니다.**

```python
def compress(text: str, **params) -> tuple[str, dict]:
    """(압축된 텍스트, 메타데이터) 를 돌려줍니다."""
    return text, {}
```

랩을 바꾼다는 건 사실상 이 함수 하나를 바꾼다는 뜻입니다. 코퍼스 로딩,
지표 계산, 결과 기록은 전부 그대로 재사용하실 수 있습니다.

## 결과는 이렇게 남습니다

실행 하나마다 `runs/<랩>/<설정>/<시각>/` 아래에 파일 네 개가 생깁니다.

| 파일 | 내용 | 커밋하나요 |
|---|---|---|
| `config.snapshot.yaml` | 설정 + kit 버전 + 실행 환경 | 예 |
| `metrics.json` | 집계 지표 | 예 |
| `report.md` | 사람이 읽는 요약 | 예 |
| `records.jsonl` | 케이스별 원문·압축문 | **아니요** |

`records.jsonl`만 커밋하지 않습니다. 용량 문제도 있지만, 더 큰 이유는
원문이 그대로 들어가기 때문입니다. 대신 압축 전후를 **둘 다** 남겨서
"이 케이스가 왜 깨졌지?"를 나중에 다시 확인하실 수 있게 했습니다.

```bash
# 가장 최근 실행에서 보존율이 낮았던 케이스 살펴보기
python - <<'PY'
import json, pathlib
d = sorted(pathlib.Path("runs").glob("*/*/*/records.jsonl"))[-1]
for line in d.read_text(encoding="utf-8").splitlines():
    r = json.loads(line)
    if (r.get("survival") or 1) < 1.0:
        print(r["id"], r["survival"])
        print("  전:", r["before"][:80])
        print("  후:", r["after"][:80])
PY
```

## 지표를 읽으실 때

`metrics.json`에는 평균뿐 아니라 **최저값과 유형별 분해**가 항상 들어갑니다.

| 항목 | 뜻 |
|---|---|
| `saved` | 절감률 |
| `survival_mean` | 정답 보존율 평균 |
| `survival_p5` | 하위 5% 지점 |
| `survival_worst` | **가장 많이 깨진 케이스** |
| `survived_all_rate` | 하나도 잃지 않은 케이스의 비율 |
| `by_kind` | 유형별로 나눈 같은 지표 |

**최저값부터 보시길 권합니다.** 평균이 90%여도 한 케이스가 0%라면 그
질문에는 답할 수 없는데, 평균은 그 사실을 가려버립니다.
